# 票面要素抽取指南

`invoice_tool.py scan` 按文件类型自动抽取：PDF 取文字层，OFD 解包取 `<TextCode>`，XML 取标签，图片无文字层需人工补录。

## 一、各票种的关键要素位置

| 要素 | 数电票 / 增值税电子发票 | 铁路电子客票 | 机票行程单 | 出租车/定额发票 |
| --- | --- | --- | --- | --- |
| 发票号码 | 票面右上「发票号码：」后 20 位（老版 8 位，另有发票代码） | 「发票号码」 | 通常无发票号码，以票号/校验码识别 | 定额发票印刷号码 |
| 开票日期 | 「开票日期：2026年11月08日」 | 「开票日期」；旧版取「乘车日期」 | 「填开日期」 | 票面日期 |
| 金额 | 「价税合计（大写）…（小写）¥1,280.00」 | 「票价」 | 「票价+民航发展基金+燃油附加费」合计 | 票面金额 |
| 不含税金额/税额 | 「合计 ¥xxx ¥yyy」 | 一般只有含税总额 | 只含总额 | 只含总额 |
| 购买方 | 「购买方信息 名称：」 | 「购买方名称」 | 常无抬头，需人工确认 | 常无抬头 |
| 销售方 | 「销售方信息 名称：」 | 铁路局集团公司 | 航空公司/销售代理 | 出租车公司 |
| 项目名称 | 「\*住宿服务\*住宿费」带星号分类简称 | 「\*运输服务\*铁路旅客运输服务」 | 「\*运输服务\*航空运输」 | 「\*运输服务\*出租车客运」 |

金额一律取「价税合计（小写）」，不要取「金额」列（那是不含税金额）。两者关系必须勾稽：不含税金额 + 税额 = 价税合计。若三者不一致，标记异常并回票面核对。

## 二、解析成功与否的判断

- `manifest.json` 中每张发票有 `score`：缺发票号码、日期、金额各扣 3 分，缺买卖方、项目名称各扣 1 分。`score < 4` 基本等于解析失败。
- 解析失败的文件进入 `skipped`，附原因。先看原因再决定补救方式，不要直接跳过。

## 三、图片与扫描件（无文字层）的处理

这是唯一需要模型参与的环节，按顺序执行：

1. 用 Read 工具直接打开图片（必要时放大或分区域查看），读出六要素：发票号码、开票日期、价税合计、购买方名称、销售方名称、项目名称。
2. 写入 overrides JSON（键为文件名，可放在待整理目录或任意位置）：

```json
{
  "出租车发票拍照.png": {
    "invoice_no": "24112000000998877665",
    "date": "2026-09-11",
    "total": 58.00,
    "amount": 56.31,
    "tax": 1.69,
    "buyer": "上海某某科技有限公司",
    "seller": "上海强生出租汽车有限公司",
    "item": "*运输服务*出租车客运",
    "invoice_type": "增值税电子普通发票",
    "note": "图像识别录入"
  }
}
```

3. 带 `--overrides` 重跑 `scan`，其余流程不变。

规则：
- 票面模糊、金额或号码无法确认时，字段留空并在 `note` 写明，不要按相似度猜数字。
- 一张图片只对应一张发票；一页多票的扫描件先拆分图片再识别。
- 识别结果必须回票面复核一次（金额、号码尤其）。

## 四、OFD / XML

- OFD 是 zip 容器，正文在 XML 的 `<TextCode>`，脚本已自动解包并按两种拼接方式择优选解析。
- 数电票 XML 字段名不完全统一，脚本按标签别名匹配（`InvoiceNumber` / `TotalTaxIncludedAmount` / `SellerName` 等）。若字段缺失，按文本正则兜底。
- 同时存在 PDF 和 XML 时只保留一份，避免重复计入。

## 五、多页合并 PDF

一页一张票的合并文件，脚本按页识别，`apply` 时拆成单票文件命名，原合并文件保留不动。拆页后必须核对页数与张数一致，再手工归档原件。

## 六、常见失败原因

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 整份文件 skipped | 加密 PDF、纯图片扫描件、版式特殊 | 解密后重跑；图片走视觉识别 |
| 金额取到 0 或异常大 | 票面有多个 ¥ 数字，取错行 | 用 overrides 指定 `total` |
| 日期 1900 年或空 | 日期写成「2026.11.08」以外的格式 | 用 overrides 补 `date`（ISO 格式） |
| 购买方/销售方颠倒 | 版式是「销售方」在左 | 在 overrides 中明确 `buyer`/`seller` |
| 一张票拆成多张 | 页码间文本重复了发票号 | 检查 `page` 字段，必要时光跑单页验证 |
